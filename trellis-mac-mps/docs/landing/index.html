A from-scratch port of Microsoft's TRELLIS to PyTorch's MPS backend and hand-written Metal kernels. Every CUDA-only stage replaced. Then benchmarked, found slow, and fixed for real — not just made to run.

The fix: binning triangles into screen-space tiles before rasterizing — the same technique nvdiffrast's own CUDA rasterizer uses (Laine & Karras, 2011) — instead of testing every pixel against every triangle. Output is bit-identical to the kernel it replaced. Full methodology, including a fix attempt that measured faster in isolation but did nothing for the real workload: the whitepaper.

Under the hood

What actually changed

No CUDA, anywhere

Sparse 3D convolution, attention, mesh rasterization, and Gaussian splat rasterization all replaced with MPS-native or pure-PyTorch equivalents.

A real Metal kernel, tile-binned

Hand-written, compiled at runtime — no Xcode required. Bins triangles into tiles instead of brute-forcing every pixel against every triangle.

A silent decimation bug, fixed

One mesh-simplification path was silently reducing meshes by 0% instead of 95% on certain non-manifold geometry. Found, diagnosed, fixed with an automatic fallback.

A local web UI and CLI

Upload an image, watch real progress, view the result in-browser — or drive it from the terminal. The original ships a Gradio demo only.

Get started

Two commands to a 3D asset

# generate from an example image
python3 cli.py generate assets/example_image/typical_creature_dragon.png dragon
# -> outputs/dragon.glb, outputs/dragon.ply

# or launch the local web UI
python3 cli.py serve
# -> http://127.0.0.1:5050

Full setup (dependencies, no CUDA toolkit needed): APPLE_SILICON.md
